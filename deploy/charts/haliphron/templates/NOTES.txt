1. Watch it come up. The first start applies the schema before it binds a
   port, so a fresh install is not ready immediately:

   kubectl -n {{ .Release.Namespace }} rollout status deploy/{{ include "haliphron.fullname" . }}

{{- if (include "haliphron.bootstrapEnabled" .) }}

2. Sign in. The API accepts nothing but a bearer token and the endpoint that
   issues tokens is itself admin-scoped, so this installation was given one:

   kubectl -n {{ .Release.Namespace }} get secret {{ include "haliphron.bootstrapSecretName" . }} \
     -o jsonpath='{.data.{{ include "haliphron.bootstrapSecretKey" . }}}' | base64 -d; echo

   It carries the admin scope{{ if .Values.bootstrapToken.ttl }} and expires in {{ .Values.bootstrapToken.ttl }}{{ else }} and does not expire{{ end }}, and it is readable by
   anyone who can read Secrets in this namespace. Treat it as what it is.
{{- if (include "haliphron.frontend.enabled" .) }}
   Paste it into the UI, mint a token of your own under Tokens, and revoke
   this one.
{{- else }}
   Use it once to mint a token of your own, then revoke it:

   curl -sX POST .../api/v1/tokens -H "Authorization: Bearer $BOOTSTRAP" \
     -H 'Content-Type: application/json' \
     -d '{"name":"ops","scopes":["admin"]}'
   {{- end }}

   Revoking it is final: the backend will not reinstate a revoked bootstrap
   token on the next restart. To install a fresh one, set bootstrapToken.value
   and upgrade.
{{- else }}

2. This release installs no bootstrap token (bootstrapToken.enabled is false),
   so the API is reachable only with a token that already exists in the
   database. If there is none, nothing can call the endpoint that issues one.
{{- end }}

3. Connect a cluster. Every target cluster needs a bootstrap token of its own
   — a different thing from the admin token above — issued by the admin API
   and used exactly once:

   kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "haliphron.fullname" . }} {{ .Values.service.ports.api }}:{{ .Values.service.ports.api }}
   curl -sX POST localhost:{{ .Values.service.ports.api }}/v1/clusters/bootstrap-tokens \
     -H "Authorization: Bearer $ADMIN_TOKEN" -H 'Content-Type: application/json' -d '{}'

   Then install haliphron-runtime into that cluster with the token and the
   Cluster API's URL as seen from inside it.

{{- if not (include "haliphron.kekEnabled" .) }}

4. No key encryption key is configured, so managed secrets are unavailable and
   the backend says so at startup. Secrets referenced from an external manager
   keep working. To enable them:

   kubectl -n {{ .Release.Namespace }} create secret generic haliphron-kek \
     --from-literal=kek="$(openssl rand -base64 32)"
   helm upgrade ... --set encryption.existingSecret=haliphron-kek

   Back the key up before you store anything under it. Losing it loses every
   managed secret, because the key is deliberately not in the database.
{{- end }}

{{- if .Values.ingress.cluster.enabled }}

   The Cluster API is exposed by an Ingress at https://{{ .Values.ingress.cluster.host }}.
   Every proxy in front of it must allow a read to hang for longer than a lease
   poll — the chart checks its own annotation, not the load balancer in front
   of your ingress controller.
{{- end }}

{{- if .Values.httpRoute.cluster.enabled }}

   The Cluster API is exposed by an HTTPRoute at {{ join ", " .Values.httpRoute.cluster.hostnames }},
   attached to Gateway {{ (first .Values.httpRoute.cluster.parentRefs).name }}. The route's own
   request timeout is checked; the Gateway's listener and whatever fronts it
   are not. Confirm the route is accepted:

   kubectl -n {{ .Release.Namespace }} get httproute {{ include "haliphron.fullname" . }}-cluster -o jsonpath='{.status.parents[*].conditions[*]}'

   A route in a namespace the Gateway does not allow is Accepted=False with
   NotAllowedByListeners, and needs a ReferenceGrant on the Gateway's side.
{{- end }}
